# OctoAcme Project Management Docs

Welcome to OctoAcme's project management guides. These documents describe how cross-functional projects are initiated, planned, delivered, released, and improved.

## Project management processes

OctoAcme uses a customer-first, iterative approach with clear ownership and data-informed decisions. Work begins by validating the need, outcomes, stakeholders, and initial risks. Approved initiatives move into planning, where teams define scope, milestones, dependencies, estimates, and acceptance criteria. During execution, teams track work on a project board, review progress and risks regularly, and use small, tested pull requests.

The Project Manager coordinates delivery, schedules, risks, and communications; the Product Manager defines outcomes, prioritizes work, and measures impact. Developers build and test against acceptance criteria, QA validates quality, and stakeholders provide input and approvals. Teams use standups, weekly delivery and PM/Product syncs, milestone demos, and regular stakeholder updates to share progress, blockers, risks, and decisions needed.

Releases require acceptance criteria to be met, passing CI and security scans, release notes, smoke tests, and a rollback or mitigation plan. Quality practices include unit tests, integration tests where applicable, end-to-end smoke tests for critical flows, security scanning, and manual QA when needed. After milestones, releases, or incidents, teams hold retrospectives and track a small set of owned improvement actions.
